# Logistics Optimization Platform

Система планування доставок для дистриб'ютора чаю та кави: адмін формує замовлення, система будує оптимальний маршрут від складу до магазинів, водій проходить його в мобільному застосунку (логіка як в Uber Eats: «Go» → навігація, «Виконано» → наступна точка).

## Документація — читай перед роботою

- `docs/SPEC.md` — технічне завдання (функціонал, модель даних, API, етапи).
- `docs/stack-decision.md` — обґрунтування вибору стеку (Flutter + Laravel + Filament).

## Прогрес — `docs/PROGRESS.md`

- Якщо задача розрослася, розбий її на підпункти в PROGRESS.md, перш ніж продовжувати.

## Стек (затверджено)

| Частина | Технологія |
| --- | --- |
| Застосунок водія | Flutter (Android + iOS), карта — `maplibre_gl` |
| Бекенд + адмінка | Laravel, адмін-панель на Filament (один моноліт) |
| Карта в адмінці | MapLibre GL JS, тайли OpenFreeMap |
| База даних | PostgreSQL + PostGIS |
| Черги | драйвер `database` у Laravel (без Redis на старті) |
| Оптимізація маршруту | VROOM + OSRM (на старті розробки можна OpenRouteService API) |
| Геокодування | Nominatim (публічний: ≤1 запит/с, без автодоповнення, кеш + атрибуція) |
| Навігація водія | посилання в Google Maps / Waze / Apple Maps |
| Розгортання | один VPS, Docker Compose |

Авторизація: серверні сесії для адмінки, токени Laravel Sanctum для застосунку водія. **Не JWT.**

## Структура репозиторію

```
mobile/    Flutter-застосунок водія
backend/   Laravel: API для водія + адмінка Filament
infra/     docker-compose, конфіги VROOM/OSRM
docs/      ТЗ і рішення
```

## Правила роботи

- Обсяг MVP — розділ 2 у `docs/SPEC.md`. Не додавай функцій із колонки «Не входить» без запиту.
- Принцип «нудно за замовчуванням»: нові сервіси чи бібліотеки — лише з обґрунтуванням (яку проблему поточний стек не розв'язує).
- Одна функція за раз; після кожного завершеного кроку — коміт.
- Модуль маршрутизації ізольований за інтерфейсом, щоб провайдера (ORS → власний VROOM/OSRM) можна було змінити без переписування решти.
- Метрики маршруту (відстань, час, пальне, вартість) зберігаються зі знімком ціни пального й часу зупинки на момент побудови.
- Мова інтерфейсу — українська, тексти в файлах локалізації.
- Час зберігається в UTC, показується в часовому поясі компанії.
- Машина розробника — Mac на Apple Silicon (arm64). Кожен Docker-образ має підтримувати linux/arm64; перевір це перед додаванням нового сервісу.

## Команди

PHP і Composer працюють **лише в Docker** — на машині розробника їх немає. Не запускай `php` чи `composer` напряму, тільки через обгортки в `bin/`.

| Дія | Команда (з кореня репозиторію) |
| --- | --- |
| Перше налаштування (образ + Laravel + міграції) | `./bin/setup` |
| Запустити бекенд і базу | `docker compose -f infra/compose.yaml up` → http://localhost:8000 |
| Зупинити | `docker compose -f infra/compose.yaml down` |
| Artisan | `./bin/artisan <команда>`, напр. `./bin/artisan migrate` |
| Composer | `./bin/composer <команда>`, напр. `./bin/composer require ...` |
| Тести бекенду | `./bin/artisan test` |

База: PostgreSQL + PostGIS у контейнері `db`, з хоста — `localhost:5432`, користувач/пароль/база `logistics` / `secret` / `logistics` (лише для розробки).

_Команди Flutter додати після створення `mobile/`._
